# Independent expected-result provenance

The four acceptance criteria and explicit validation requirements come only from the current IG-1C queue/card and the freshly generated reviewer packet. Frozen corpus counts were recomputed; neither old gold/answers nor executor counters generated the expected inventory. The packet includes an execution skill as tool-generated context; this reviewer applies only the explicitly requested local wgc-review skill and does not execute or claim product work.

Raw input expectations come from the exact pinned input manifest, each explicitly enumerated available blob, the selected registry manifest and source pin. yaml.safe_load decodes the actual frozen corpus separately from the adapter; yaml.compose supplies an independent full node/path/mark ledger. The audit checks every file, record, nested parent, full value, anonymous external identity, unknown-field location, navigation entry and not-granted acceptance/readiness marker. Every one of the 38,206 field/container records is compared for its pointer, YAML tag, character range and source/key line/column. The corpus is required to be JSON-safe instead of being silently converted to the product's special-scalar representation. Each record has a full value equality check and a value hash. Representative mappings of every kind are retained privately in the independent report.

Unknown-field inventory is deliberately conservative: every mapping field without a definition in the pinned WGU schema, recursively including untyped table payload, auxiliary metadata and terminology, is checked against the document and complete field ledger. This yields 8,904 locations; it is a different definition from the adapter's immediate unknown-field list and does not claim those fields have accepted meanings. Terminology is explicitly in task scope even though its field schema is not in the four support files.

The four exact external support files were rehashed before use. The WGU schema and store define collections, recursive procedures, required record shapes, optional field types and enums. The exporter is examined as an incomplete derived-input route; it is never invoked. The linter is examined for structural-contract expectations; it is not invoked because doing so would broaden neighboring reads. Full schema expectations are not gameplay legality or human semantic acceptance. Imported answers, given/when/then values, verified relations, complete tables, resolved ambiguities and terminology decisions are retained without being treated as expected gameplay truth.

The malformed safe-tag tests expect explicit raw/error accounting because invalid input must not abort complete input accounting. The known-field tests use the pinned schema's definition/string type, flags enum, table array shape and relation.type enum. The confusables oracle uses its explicitly unconstrained item schema and therefore expects valid scalar entries to survive without false errors. All seven failing assertions remain strict and unchanged. No production repair or product-finding repair cycle was performed.

The recursion, alias expansion and depth tests use actual production limits: a compact eight-way alias tree exceeds the expansion budget and 110 nested sequences exceed the depth limit. Unsafe Python tags, duplicate nested keys, multiple YAML documents, complex keys and merge keys must be errors; bytes and required unsafe/duplicate diagnostic source locations must survive. Duplicate recognized IDs retain both occurrences; auxiliary identifiers are not entity IDs. Anonymous terms, escaped unknown paths and nested string numbering are preserved. Binary auxiliary files retain exact bytes. Questions remain evaluation candidates and refs/see remain navigation.

Dependency verification is offline: saved official PyPI 6.0.3 metadata pins the wheel URL/hash; all 23 non-RECORD installed wheel files match its source/extension/metadata bytes. The installed RECORD is intentionally excluded because installation rewrites it. No network, package install, external API, archive, Git-history or past-chat evidence was used.

The separate input-test sandbox attempt failed on native Windows handle verification and filesystem operations; all 51 tests subsequently passed under a normally reviewed narrow local escalation with fresh temporary paths. This is an environment-condition change, not an unchanged retry or weakened assertion. The real Windows junction tests ran. Native file/directory symlink behavior remains unmeasured (null); junctions are not reported as symlinks. No no-follow check was bypassed. The full project check passed independently in its own project-local temporary environment.
