# Deterministic source export

The operator-approved `wgc-source-export-1` profile retains every source-v1
mechanical, hash, reference, review and readiness invariant. Its version is explicit;
canonical `run.started_utc` and `run.ended_utc` must be null. Actual operation/session
evidence is stored outside canonical packages. Original IG-1A contracts and validator
bytes remain unchanged; validation uses that validator with the explicit profile.

Identity IDs and origin keys come from persisted allocation counters. Value/label
descriptors only justify rematching. Reorders and unambiguous edits reuse allocations;
duplicate observations, conflicting matches and insufficient rename evidence retain
gaps. Explicit binding decisions support many-to-many mappings. Explicit split/merge
decisions allocate children and retain parent identities and exact prior revisions.
No lineage or imported status transfers semantic acceptance. File source entries use
explicit declared external origins; anonymous KB identities never use file locators
as their identity generators. Provenance binding records describe immutable snapshot
coordinates; those coordinates can contain original array indices.

The canonical registry preserves every complete raw observation, current origin and
historical binding. Original raw bytes and all nested field marks remain in the pinned
IG-1C input/import. Source nodes expose stable top-field aspects and dedicated clause,
concept, procedure, step and table descriptions. Publisher-source meaning remains
unknown with explicit gaps. Unreconciled table axes are marked placeholders; cells,
units, composition and source evidence remain pending. Raw table/unknown-field data is
retained in registry observations and exact subtree origin bindings. No PDF page or
publisher quotation is fabricated to turn KB metadata into accepted evidence.

Refs/see remain navigation. Relationship projections are unaccepted informational
candidates with unknown applicability, plus raw values in the registry. Exact current
identifiers/unique stored aliases resolve; wildcard/subpoint scopes require explicit
exact target sets and a basis. Other scopes remain unresolved. Cycles are diagnostics;
the rule/procedure graph is not required to be a DAG.

`source.build` is a pure transform. Supply the previous registry to preserve identities
and the previous bundle to retain revision history/supersession and exact split/merge
lineage. Repeating unchanged input with those same persisted outputs adds no revisions,
allocations or canonical timestamps. `storage.publish` never overwrites a package;
reuse verifies exact tree names and bytes. A partial/corrupt existing package is retained
and fails explicitly. Real operation clocks/measurements are separate sidecars.

These artifacts provide structural import/mapping, not full publisher-source coverage,
human semantic acceptance, game semantics, a compiler, or executable readiness.
