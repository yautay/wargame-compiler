# Handoff: M-INF0 Korekta architektury: self-hosted inference na węźle w LAN (2026-10-05)
- **Model/rola:** Opus 5.5, Architecture Model
- **Wynik:** done

## Dlaczego
Właściciel ma **osobny komputer inferencji w LAN**: Windows 11 Pro, RTX 3090 24 GB, Ryzen klasy 9800X3D, 128 GB RAM.
Maszyna z Claude Desktop to inny host bez GPU. Session 0 zakładała model na `127.0.0.1` w WSL2 na tej samej maszynie
co GLU (ADR-0008) i GLU łączący się wprost z runtime'em (ADR-0009). Ta sesja koryguje architekturę, kontrakty
i roadmapę. Kodu nie ma.

## Zrobione
- **Pojęcia.** „local” = self-hosted, nie localhost. Tier `local` i profile `local_*` zachowują nazwy, a zmienia się
  ich definicja.
- **Węzeł.** Wymienialny worker: nie zna WGC, nie jest źródłem prawdy, nie przechowuje promptów, KB ani cache wyników.
- **ADR-0015…0018:**
  - 0015: węzeł w LAN, zastępuje ADR-0008;
  - 0016: Inference Gateway `igw` i protokół `igw/api@0`, zastępuje ADR-0009;
  - 0017: brak automatycznego premium fallbacku, self-hosted jako zasób obfity, lokalny multi-pass;
  - 0018: runtime MVP to llama.cpp natywnie na Windows, vLLM w WSL2 tylko po benchmarku.

  Fakty o llama.cpp sprawdzone w dokumentacji projektu, o vLLM w źródłach wtórnych (2026-10-05, lista w ADR-0018): ograniczenia JSON Schema → GBNF, tryb
  routera, `--n-cpu-moe`, brak oficjalnego vLLM na Windows.

## Ryzyka i pułapki odkryte w sesji
- Konwerter JSON Schema → GBNF w llama.cpp **pomija nieobsługiwane cechy po cichu** (`if/then/else`, `not`,
  `allOf` z dispatch). Schematy WGC z `allOf`/`if` nie mogą iść do dekodowania bez spłaszczenia (`decoding_schema`).
- Konwencja `Mn.a` z SESSION-PLAYBOOK nie przejdzie testu ciągłości (regex `M[\w-]+` nie dopuszcza kropki). Nazwy
  milestone'ów: `M-XXX` albo `Mna`.
- Heredoc w Git Bash z polskim tekstem i backtickami znów się nie sparsował. Edycje dokumentów rób skryptem
  zapisanym narzędziem Write.
- `STATUS.md` podawał remote z literówką (`wargame-complier`). Poprawione na faktyczny `git@github.com:yautay/wargame-compiler.git`.
